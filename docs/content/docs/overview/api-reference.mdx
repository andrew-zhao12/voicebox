Voicebox speaks two APIs on the same port and with the same [API keys](/overview/api-keys):

- **`/v1`, OpenAI-compatible.** Speech and transcription in the shape the OpenAI SDKs expect, so any OpenAI client works with `base_url` pointed at your server. This is the surface to build applications on, and the one voice agents use: [LiveKit Agents](/integrations/livekit) runs on it through LiveKit's stock OpenAI plugin.
- **The native API.** Everything the desktop UI uses: profiles, samples, history, stories, captures, models, settings. Its interactive reference is at `/docs` on a running server (unless `VOICEBOX_DISABLE_DOCS=1`), and the schema is in the repo at `docs/openapi.json`.

Every request carries `Authorization: Bearer <key>`. Give each application its own **client** key; it can synthesize, transcribe, and read profiles and models, and nothing else.

## Speech: `POST /v1/audio/speech`

```json
{
  "model": "tts-1",
  "input": "Hello from Voicebox.",
  "voice": "Narrator",
  "response_format": "mp3"
}
```

| Field | Meaning |
|-------|---------|
| `voice` | Resolved in this order: a voice profile **id**, a profile **name**, a built-in **preset voice id** (`af_heart`, `Ryan`, or qualified as `kokoro:af_heart`), then OpenAI's stock names (`alloy`, `nova`, ...), which select the configured default voice (the per-client binding, else the default playback voice from Settings → MCP). `GET /v1/voices` lists every value. Voices another client key created are not visible. |
| `model` | `tts-1`, `tts-1-hd` or `gpt-4o-mini-tts` use the voice's default engine. Otherwise a model or engine name from `GET /v1/models`: `kokoro`, `qwen-tts-1.7B`, `qwen-tts-0.6B`, `chatterbox-turbo`, `luxtts`, `tada-1b`, ... A preset voice only works with its own engine. |
| `response_format` | `mp3` (default), `opus`, `aac`, `flac`, `wav`, `pcm` (signed 16-bit little-endian mono at 24 kHz, the rate OpenAI clients assume for raw audio; resampled when the engine's rate differs), `ulaw_8000` (G.711 mu-law at 8 kHz for telephony, band-limited before the sample rate drops). |
| `instructions` | Style hint, passed as the engine's `instruct` where the engine supports it (Qwen CustomVoice). |
| `language` | Voicebox extension: language code of the input. Defaults to the profile's language. |
| `speed` | `0.25` to `4.0` (default `1.0`). Kokoro speaks at that rate natively; every other engine is time-stretched after synthesis with the pitch preserved, chunk by chunk, so streaming is unaffected. |
| `max_chunk_chars`, `first_chunk_chars` | Voicebox extension: caps on the characters synthesized per chunk (defaults `800` and `120`, minimums `100` and `20`). Smaller chunks start audio sooner and bound how much a cancelled request still renders. |

The response is always chunked. `wav`, `pcm` and `ulaw_8000` leave the server sentence by sentence as synthesis proceeds; the compressed formats stream too when ffmpeg is installed (it is in the Docker image) and are otherwise sent once the clip is complete. `X-Voicebox-Sample-Rate` is the sample rate of the audio in the response: `24000` for `pcm`, `8000` for `ulaw_8000`, and the engine's own rate for `wav` and the compressed formats (24 kHz for most engines, 48 kHz for LuxTTS). `X-Voicebox-Engine` names the engine used and `X-Voicebox-Voice` the resolved voice (a profile id, or `engine:voice_id` for a preset). Nothing is written to the generation history.

The status line and headers leave with the first chunk, so a request refused before any audio exists (unknown voice, full queue, model not downloaded) still gets its real status code. A client that hangs up before the first chunk gives the job up: still queued, it is skipped; already running, it stops when the engine call in progress returns. The server records such a request as `499`, and its characters stay charged to `tts_chars`. Hanging up later stops the job after the chunk being synthesized. If synthesis fails after the first chunk, the server drops the connection without ending the chunked body, so the client sees an incomplete transfer (an error in most HTTP libraries) instead of a short clip that looks complete.

Voice agents built on [LiveKit Agents](/integrations/livekit) use this endpoint through LiveKit's OpenAI plugin, one request per sentence.

**Python (OpenAI SDK)**

```python
from openai import OpenAI

client = OpenAI(base_url="https://voice.example.com/v1", api_key="vbx_...")

with client.audio.speech.with_streaming_response.create(
    model="kokoro",
    voice="Narrator",
    input="Hello from Voicebox.",
    response_format="mp3",
) as response:
    response.stream_to_file("hello.mp3")
```

**Node (OpenAI SDK)**

```ts
import OpenAI from 'openai';

const client = new OpenAI({ baseURL: 'https://voice.example.com/v1', apiKey: 'vbx_...' });
const response = await client.audio.speech.create({
  model: 'tts-1',
  voice: 'Narrator',
  input: 'Hello from Voicebox.',
  response_format: 'wav',
});
// response.body is a stream; the first bytes arrive after the first sentence.
```

**curl**

```bash
curl -N https://voice.example.com/v1/audio/speech \
  -H "Authorization: Bearer $VOICEBOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"tts-1","voice":"Narrator","input":"Hello from Voicebox.","response_format":"wav"}' \
  --output hello.wav
```

## Transcription: `POST /v1/audio/transcriptions`

Multipart form with `file` (wav, mp3, m4a, ogg, flac, aac, webm, opus; 200 MB cap), `model` and optional `language` and `response_format`.

- `model`: `whisper-1` uses the server's current Whisper size; `whisper-turbo`, `whisper-large`, `whisper-medium`, `whisper-small` or `whisper-base` pick one explicitly.
- `response_format`: `json` (default, `{"text": "..."}`), `text`, `verbose_json` (OpenAI's shape with `duration`, `language` and `segments[]` carrying `start`, `end` and `text`), `srt` or `vtt` (subtitle cues, one per Whisper segment). `timestamp_granularities[]=segment` is accepted; `word` is refused with `400`, word timestamps do not exist.
- The model must already be downloaded; client keys get a `409` otherwise (preload it with `VOICEBOX_PRELOAD_MODELS=whisper-turbo`).

```python
with open("meeting.m4a", "rb") as audio:
    result = client.audio.transcriptions.create(model="whisper-turbo", file=audio, language="en")
print(result.text)

with open("meeting.m4a", "rb") as audio:
    detailed = client.audio.transcriptions.create(model="whisper-turbo", file=audio, response_format="verbose_json")
for segment in detailed.segments:
    print(f"{segment.start:6.2f}-{segment.end:6.2f}  {segment.text}")
```

## Live transcription: `WS /v1/realtime`

For conversation features, stream microphone audio over a WebSocket and receive partial text while the user speaks and a final transcript per utterance. Whisper is not a streaming model, so "live" means utterances are cut by a server-side voice activity detector (or by your commits) and each one is transcribed as it ends, with partial passes every second in between. Two paths serve the same sessions:

| Path | Protocol |
|------|----------|
| `/v1/realtime?intent=transcription` | OpenAI's GA Realtime transcription protocol: `session.created` and `session.updated` carry a `realtime.transcription_session` object. LiveKit's `openai.STT(use_realtime=True)` connects here unmodified (see [LiveKit Agents](/integrations/livekit)). Any other `intent` is refused with `unsupported_intent` and close `1008`; conversation sessions are not served. |
| `/v1/realtime/transcription` | Voicebox's original dialect, with OpenAI's beta event names: `transcription_session.created` and `.updated` carry the flat session object. |

Both paths read either shape of session update and take `?model=` (for example `?model=whisper-turbo`), which sets the session's model as it opens. The model is checked at that moment: an unknown name (`model_not_found`) or, for a client key, a size that is not downloaded (`model_not_downloaded`) closes the socket with `1008`. A model set later by a session update is checked the same way but only answered with an `error` event, and the session keeps its previous settings. The paths differ only in their session events and in which closes an `error` event announces (see Closing below).

- **Connect** with `Authorization: Bearer <client key>`; browsers, which cannot set WebSocket headers, pass a media token instead: `wss://host/v1/realtime?intent=transcription&token=<POST /auth/media-token>`. A missing or invalid key fails the handshake with HTTP `403`.
- **Configure** with `session.update` (alias `transcription_session.update`), in the GA shape or the flat one. Fields left out keep their value.

  ```json
  {"type": "session.update", "session": {"type": "transcription", "audio": {"input": {
    "format": {"type": "audio/pcm", "rate": 24000},
    "transcription": {"model": "whisper-turbo", "language": "en"},
    "turn_detection": {"type": "server_vad", "threshold": 0.5, "prefix_padding_ms": 300, "silence_duration_ms": 500}
  }}}}
  ```

  ```json
  {"type": "transcription_session.update", "session": {
    "input_audio_format": "pcm16", "input_sample_rate": 16000,
    "input_audio_transcription": {"model": "whisper-turbo", "language": "en"},
    "turn_detection": {"type": "server_vad", "threshold": 0.5, "prefix_padding_ms": 300, "silence_duration_ms": 500},
    "partial_interval_ms": 1000
  }}
  ```

  | Setting | GA (under `session.audio.input`) | Flat | Values |
  |---------|----------------------------------|------|--------|
  | Format | `format.type` | `input_audio_format` | `audio/pcm` or `pcm16` (signed 16-bit little-endian mono); `audio/pcmu` or `g711_ulaw`, `audio/pcma` or `g711_alaw` (G.711 mu-law and A-law, always 8 kHz) |
  | PCM sample rate | `format.rate` | `input_sample_rate` | 8000, 16000, 22050, 24000 (default), 44100 or 48000; OpenAI itself accepts only 24000 |
  | Model and language | `transcription` | `input_audio_transcription` | `model` as for `/v1/audio/transcriptions`, `language` (up to 32 characters), and `prompt` (up to 4,096 characters), which is stored and echoed but not passed to Whisper yet |
  | Turn detection | `turn_detection` | `turn_detection` | `server_vad` with `threshold` (0–1), `prefix_padding_ms` (0–2000) and `silence_duration_ms` (100–5000), or `null` for manual turns; `semantic_vad` is refused |
  | Partial interval | `partial_interval_ms` (on `session`) | `partial_interval_ms` | 300–10000 ms, default 1000; a Voicebox extension |

  Other GA settings (`noise_reduction`, `include`, `idle_timeout_ms`, ...) are ignored. A value out of range gets an `invalid_session` error and leaves the session as it was.
- **Send audio** as `input_audio_buffer.append` with `audio` holding base64 in the session's format, or as raw binary frames. The server resamples it to Whisper's 16 kHz with one filter for the whole stream, so chunk size does not matter. `input_audio_buffer.commit` ends the current utterance now (required with `turn_detection: null`), `input_audio_buffer.clear` discards it.
- **Receive** these events. Every event carries its own `event_id`.

  | Event | Fields |
  |-------|--------|
  | `session.created` / `session.updated` (GA path), `transcription_session.created` / `.updated` (Voicebox path) | `session` |
  | `input_audio_buffer.speech_started` / `.speech_stopped` | `item_id`, `audio_start_ms` / `audio_end_ms` |
  | `input_audio_buffer.committed` | `item_id`, `previous_item_id` (`null` for the first utterance) |
  | `input_audio_buffer.cleared` | |
  | `conversation.item.input_audio_transcription.delta` | `item_id`, `content_index` (always `0`), `delta` |
  | `conversation.item.input_audio_transcription.completed` | `item_id`, `content_index`, `transcript`, `usage` (`{"type": "duration", "seconds": ...}`, the audio sent to Whisper) |
  | `conversation.item.input_audio_transcription.failed` | `item_id`, `content_index`, `error` with a `code`: `transcription_failed`, `whisper_busy` or `session_closed` |
  | `error` | `error` with `type`, `code`, `message`, and `event_id` when the client event that caused it had one |

  Deltas are append-only: only the words two consecutive passes agree on are sent, and `completed` is the authoritative text (it may revise earlier deltas).
- **Limits**: messages up to 1 MiB, utterances are cut at 30 s (one Whisper window), sessions end after `VOICEBOX_REALTIME_IDLE_S` seconds without a message (default 60, minimum 15) or after `VOICEBOX_REALTIME_MAX_SESSION_S` (default 1800), at most `VOICEBOX_REALTIME_MAX_SESSIONS` (default 4) sessions per server and `max_realtime_sessions` per key (default 2). At most eight utterances of a session wait for their final pass at once; the next one fails straight away with `whisper_busy`, so audio sent faster than Whisper transcribes it is dropped rather than queued. Every session costs one `inference` request and the audio counts against `uploads_bytes`.

**Closing.** The close reason is the code word in the table. Before an idle, too-long or shutdown close, the server commits the utterance in progress, stops partials, ignores further audio and delivers the pending finals, waiting up to 10 s (and no longer than `VOICEBOX_DRAIN_TIMEOUT_S` while the server stops); a final still missing after that arrives as `...failed` with code `session_closed`. On shutdown this needs `VOICEBOX_SHUTDOWN_DELAY_S` above 0 (see [Deployment](/overview/deployment#5-graceful-stop)); without it the socket closes as soon as the signal arrives and the utterance in progress is lost.

| Close | Reason | When |
|-------|--------|------|
| `1000` | `idle_timeout`, `session_too_long` | No message for `VOICEBOX_REALTIME_IDLE_S`; the session reached `VOICEBOX_REALTIME_MAX_SESSION_S` |
| `1008` | `unsupported_intent`, `model_not_found`, `model_not_downloaded`, `message_too_large` | The session cannot be served as asked |
| `1011` | `server_error` | The session failed inside the server |
| `1012` | `server_shutting_down` | The server is stopping; reconnect |
| `1013` | `session_limit_reached`, `rate_limit_exceeded` | Session cap or rate limit; try again later |

On `/v1/realtime/transcription` every close except `1011` is preceded by an `error` event with the same code. On `/v1/realtime` only the `1008` closes are, because OpenAI clients treat any `error` event as fatal: the other closes come without one, and the client reconnects.

```python
import asyncio, base64, json, websockets

async def main():
    async with websockets.connect(
        "wss://voice.example.com/v1/realtime?intent=transcription&model=whisper-turbo",
        additional_headers={"Authorization": "Bearer vbx_..."},
    ) as ws:
        await ws.send(json.dumps({"type": "session.update", "session": {"type": "transcription", "audio": {"input": {
            "format": {"type": "audio/pcm", "rate": 16000}, "transcription": {"language": "en"}}}}}))
        async def send_audio():
            async for pcm16_chunk in microphone():  # your capture loop, 16 kHz mono PCM16
                await ws.send(json.dumps({"type": "input_audio_buffer.append", "audio": base64.b64encode(pcm16_chunk).decode()}))
        asyncio.create_task(send_audio())
        async for message in ws:
            event = json.loads(message)
            if event["type"].endswith("transcription.delta"):
                print(event["delta"], end="", flush=True)
            elif event["type"].endswith("transcription.completed"):
                print("\n=>", event["transcript"])

asyncio.run(main())
```

`scripts/realtime_client.py` in the repository streams a WAV file to `/v1/realtime/transcription` at real-time pace and prints the events, which is the quickest way to try a server.

## Discovery: `GET /v1`, `GET /v1/models` and `GET /v1/voices`

`/v1` (and `/v1/`) answers any valid key with `{"object": "service", "name": "voicebox", "version": "..."}`. OpenAI clients fetch it to open a connection ahead of the first request, as LiveKit's TTS plugin does when a session starts.

`/v1/models` lists every TTS and STT model with `engine`, `kind` (`tts`/`stt`), `languages`, `supports_instruct`, `downloaded` and `loaded`, plus a top-level `formats` array with the `response_format` values this server can produce.

`/v1/voices` lists everything the `voice` field accepts: the profiles visible to the caller (`kind: "profile"`, with `id`, `name`, `language`, `voice_type`, `engine`, `owner` and `shared`) followed by the built-in preset voices (`kind: "preset"`, with the preset id as `id`, plus `engine`, `language` and `gender`).

## Voices: `POST /v1/voices` and `DELETE /v1/voices/{voice}`

An application can clone voices of its own without the admin UI. `POST /v1/voices` is a multipart form:

| Field | Meaning |
|-------|---------|
| `name` | Unique profile name (1–100 characters); also usable as the `voice` value. |
| `file` | One to ten reference recordings (wav, mp3, m4a, ogg, flac, aac, webm, opus), 2–30 seconds each, 50 MB per file, 100 MB per request. |
| `text` | Optional transcript per file, in order. Files without one are transcribed with Whisper (the model must be downloaded; otherwise `409`). |
| `language` | Language code, default `en`. |
| `engine` | Default cloning engine (`qwen`, `luxtts`, `chatterbox`, `chatterbox_turbo`, `tada`); `qwen` when omitted. |
| `description` | Free text. |

The response (`201`) is the voice entry as `GET /v1/voices` lists it. A voice created this way belongs to the key that created it: other client keys neither see nor use it, admin keys see everything. Each key may hold `max_voices` of them (default 50, adjustable per key). `DELETE /v1/voices/{voice}` (id or name) removes a voice the key owns and answers `{"id": ..., "deleted": true}`; shared voices created by an admin answer `403`, presets `404`.

```bash
curl https://voice.example.com/v1/voices \
  -H "Authorization: Bearer $VOICEBOX_API_KEY" \
  -F name="Support Bot" -F engine=qwen \
  -F file=@sample1.wav -F text="First sentence of the first sample." \
  -F file=@sample2.wav
```

```python
import httpx

with open("sample1.wav", "rb") as sample:
    voice = httpx.post(
        "https://voice.example.com/v1/voices",
        headers={"Authorization": "Bearer vbx_..."},
        data={"name": "Support Bot", "engine": "qwen", "text": "First sentence of the sample."},
        files={"file": sample},
        timeout=120,
    ).json()
# then: client.audio.speech.create(model="tts-1", voice=voice["name"], input=...)
```

## Errors

Under `/v1`, errors use OpenAI's envelope, so SDK exceptions carry the message:

```json
{ "error": { "message": "No voice profile named 'Narrator'; GET /v1/voices lists the voice profiles.", "type": "invalid_request_error", "param": "voice", "code": "voice_not_found" } }
```

| Status | `type` | When |
|--------|--------|------|
| 400 | `invalid_request_error` | Bad body (`invalid_value`, including `speed` outside 0.25–4.0), unsupported `response_format`, `voice_engine_mismatch` (`param: "voice"`: a preset of another engine, or a cloned voice on Kokoro or `qwen_custom_voice`; pick a voice of the requested engine or send `tts-1`), a speech model that is not downloaded |
| 401 | `authentication_error` | Missing or invalid key |
| 403 | `permission_error` | A client key on an admin route; `voice_not_owned` (deleting a shared voice), `voice_limit_reached` |
| 404 | `invalid_request_error` | `voice_not_found`, `model_not_found` |
| 409 | `invalid_request_error` | A Whisper model that is not downloaded (client keys); `voice_exists` |
| 413 | `invalid_request_error` | A sample or request body above its cap |
| 429 | `rate_limit_error` | Per-key limits, a full queue or a busy Whisper; honour `Retry-After` (a WebSocket session closes with `1013`, announced by an `error` event only on `/v1/realtime/transcription`) |
| 503 | `server_error` | The server is draining before a restart; retry after `Retry-After` |

Responses also carry `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset` (see [API Keys → Rate limits](/overview/api-keys#rate-limits)).

## Native endpoints worth knowing

| Endpoint | Purpose |
|----------|---------|
| `POST /generate/stream` | The same streaming synthesis with Voicebox's own body (`profile_id`, `engine`, `effects_chain`, `seed`, `speed`, chunking controls), as `wav` or `pcm` at the engine's own rate. |
| `POST /generate` then `GET /generate/{id}/status` | Queue a generation that is saved to history; progress over SSE, audio at `GET /audio/{id}`. |
| `POST /speak` | Speak through the profile bound to an `X-Voicebox-Client-Id` (agents). |
| `POST /transcribe` | Transcription with `{"text", "duration"}`. |
| `GET /profiles`, `GET /profiles/{id}` | Voice profiles (client keys see shared ones and their own). |
| `GET /health/ready` | Readiness probe, no key needed. |

Editing profiles, uploading samples to shared voices and managing models are admin operations: do them in the UI, or with the admin key against the routes in `/docs`. Applications clone their own voices through `POST /v1/voices` above.
