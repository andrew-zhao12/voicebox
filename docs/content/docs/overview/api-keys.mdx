## Overview

<Callout type="info">
  Building an application? The [API Reference](/overview/api-reference) covers the OpenAI-compatible `/v1` endpoints your app will call with a client key.
</Callout>

Every request to the Voicebox API needs an API key, sent as a bearer token:

```
Authorization: Bearer vbx_...
```

The rule covers the REST API, the MCP server at `/mcp` and the web UI alike. The desktop app needs no setup: it creates its own key on first launch and uses it automatically. You only deal with keys when you call the API from your own code, connect an agent or the web UI to a server, or run Voicebox headless (Docker, a GPU box).

Keys are random secrets that start with `vbx_`. Treat them like passwords: send them only over `localhost` or HTTPS, and keep them out of repositories and config files that sync to the cloud.

<Callout type="info">
  There is no "auth off" switch. A server that starts without a configured key generates one, so nothing ever listens unprotected. If you want to switch off the *rate limits* (not the keys) on a trusted machine, set `VOICEBOX_RATE_LIMITING=0`.
</Callout>

## Roles

Each key has one of two roles.

| Role | Who uses it | What it can do |
|------|-------------|----------------|
| `admin` | Desktop app, web UI, operators | Everything: settings, history, captures, model downloads, key management, `/shutdown` |
| `client` | Your own apps, scripts and agents | Generate and stream speech, `/speak`, transcribe, cancel and follow generations, read profiles, presets, model status and the effects list, fetch generation audio and metadata |

The full list of routes a client key may call:

| Method | Route |
|--------|-------|
| POST | `/generate`, `/generate/stream`, `/speak` |
| POST | `/generate/{id}/cancel` |
| GET | `/generate/{id}/status` (SSE progress) |
| POST | `/transcribe` |
| GET | `/history/{id}`, `/audio/{id}`, `/audio/version/{id}` |
| GET | `/profiles`, `/profiles/{id}`, `/profiles/{id}/avatar`, `/profiles/presets/{engine}` |
| GET | `/models/status`, `/effects/available`, `/health` |
| GET | `/auth/whoami` |
| POST | `/auth/media-token` |
| MCP | `/mcp` — the `voicebox.speak`, `voicebox.transcribe` (base64 audio) and `voicebox.list_profiles` tools |

Everything else is admin-only. A client key on an admin route gets `403`; a request without a key gets `401`. Unknown paths answer the same way, so nobody can map the API without a key.

Two things to plan for when you build on a client key:

- **Models must already be downloaded.** Client keys can't trigger downloads. `/generate` and `/generate/stream` answer `400` and `/transcribe` answers `409` while the model is missing. Download it from the desktop app or with an admin key (`POST /models/download`) first.
- **Keys don't partition data.** Any client key can list every profile and fetch any generation by id. Per-key ownership is not implemented.

## Where your key lives

The server merges keys from three sources. Which one you use depends on how you run Voicebox.

| Source | Role | Notes |
|--------|------|-------|
| `VOICEBOX_API_KEY` environment variable | admin, id `env` | One admin key for Docker and headless servers. When it is set, no key file is created. |
| `<data-dir>/api_key` | admin, id `local` | Plain-text file created on first start with mode `0600` when there is no environment key. The desktop app uses this one. Override the path with `VOICEBOX_API_KEY_FILE`. |
| `<data-dir>/api_keys.json` | admin or client, per key | Hashed store for the keys you create for your own apps, managed by the `backend.keys` CLI and the `/auth/keys` routes. Override the path with `VOICEBOX_API_KEYS_JSON`. |

The startup log names the key file's path but never prints a key.

### Desktop app

Nothing to configure. The app creates `api_key` in its data directory on first launch and sends it with every request. Because it is an admin key, it also works for MCP clients and `curl` on the same machine:

| OS | Path |
|----|------|
| macOS | `~/Library/Application Support/sh.voicebox.app/api_key` |
| Windows | `%APPDATA%\sh.voicebox.app\api_key` |
| Linux | `~/.local/share/sh.voicebox.app/api_key` |

**Settings → MCP** has a **Copy API key** button so you never have to open the file, and the bundled stdio shim (`voicebox-mcp`) reads the file automatically when it runs on the same machine.

### `just dev` and `just dev-web`

Both recipes create `<repo>/data/api_key` before the backend starts and hand it to the desktop shell or the web dev server, so the UI connects without asking. From a terminal:

```bash
export VOICEBOX_API_KEY="$(just api-key)"   # prints the dev key, creating it if needed
curl -H "Authorization: Bearer $VOICEBOX_API_KEY" http://127.0.0.1:17493/profiles
```

`just dev-backend` on its own also creates `data/api_key` on first start.

### Docker

`docker-compose.yml` passes `VOICEBOX_API_KEY` through from your shell. Set it before the first start:

```bash
export VOICEBOX_API_KEY="$(openssl rand -base64 32)"
docker compose up -d --build
```

Without it, the container creates `/app/data/api_key` in the `voicebox-data` volume:

```bash
docker compose exec voicebox cat /app/data/api_key
```

The web UI at `http://localhost:17600` opens on a **Connect** screen that asks for the server URL and this key. See [Docker Deployment](/overview/docker) for the TLS overlay and the rest of the container setup.

### Headless server from a checkout

Run the backend from the repo root. Either export a fixed admin key or let the server create one in the data directory:

```bash
# A fixed admin key from the environment
export VOICEBOX_API_KEY="$(openssl rand -base64 32)"
backend/venv/bin/python -m backend.main --host 0.0.0.0 --port 17493 --data-dir /srv/voicebox

# ...or read the key the server generated on first start
backend/venv/bin/python -m backend.keys local --data-dir /srv/voicebox
```

Set `VOICEBOX_DISABLE_DOCS=1` on servers that don't need the interactive `/docs` page.

## Creating keys for your apps

Give each app its own `client` key so you can revoke it and tune its limits without touching anything else. Keep the admin key for the UI and for operators.

### With the CLI

Run it from the repo root with the backend venv. `--data-dir` must point at the data directory of the server you are managing; leave it out for the dev server (`<repo>/data`).

```bash
# Create a client key. The key is printed once; store it now.
backend/venv/bin/python -m backend.keys create --id myapp --role client

# Custom limits for this key
backend/venv/bin/python -m backend.keys create --id batch-job --role client \
  --limit requests=600 --limit inference=60

backend/venv/bin/python -m backend.keys list
backend/venv/bin/python -m backend.keys revoke --id myapp
```

Inside the Docker container the same CLI is available; run it as the `voicebox` user so the server can read the file it writes:

```bash
docker compose exec -u voicebox voicebox python -m backend.keys create --id myapp --role client
```

Key ids are 1–32 characters of lowercase letters, digits, `-` and `_`; `env` and `local` are reserved. A running server notices changes to `api_keys.json` within a second, so new and revoked keys take effect without a restart.

### With the REST API

Any admin key can manage keys over HTTP, which is the way to go for the desktop app's server or a remote box.

```bash
# Create (the plaintext key is returned once)
curl -X POST http://127.0.0.1:17493/auth/keys \
  -H "Authorization: Bearer $VOICEBOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"id": "myapp", "role": "client"}'

# List (ids, roles, limits; never the keys themselves)
curl -H "Authorization: Bearer $VOICEBOX_API_KEY" http://127.0.0.1:17493/auth/keys

# Revoke
curl -X DELETE -H "Authorization: Bearer $VOICEBOX_API_KEY" http://127.0.0.1:17493/auth/keys/myapp
```

`POST /auth/keys` answers `201` with the key, `409` if the id exists and `400` for an invalid or reserved id. `DELETE` answers `204`; it refuses `env`, `local` and the key you are calling with. Add a `limits` object to the create body to override rate limits for that key (fields under [Rate limits](#rate-limits)).

## Using a key

### curl and HTTP clients

```bash
curl -X POST http://127.0.0.1:17493/generate \
  -H "Authorization: Bearer $VOICEBOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello world", "profile_id": "abc123", "engine": "kokoro"}'
```

`GET /auth/whoami` tells you which key the server sees and what it may do:

```bash
curl -H "Authorization: Bearer $VOICEBOX_API_KEY" http://127.0.0.1:17493/auth/whoami
# {"key_id": "myapp", "role": "client", "via": "header", "limits": {...}}
```

### fetch from your own web app

```ts
const res = await fetch("http://127.0.0.1:17493/generate", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ text: "Hello world", profile_id: "abc123" }),
});
```

If the page is served from a different origin than the API, add that origin to `VOICEBOX_CORS_ORIGINS` on the server.

### EventSource, audio and image tags

`EventSource`, `<audio src>`, `<img src>` and similar loads can't send headers. For those, ask the server for a short-lived **media token** and pass it as a `token` query parameter:

```ts
const { token, expires_in } = await fetch("http://127.0.0.1:17493/auth/media-token", {
  method: "POST",
  headers: { Authorization: `Bearer ${apiKey}` },
}).then((r) => r.json());

const progress = new EventSource(`http://127.0.0.1:17493/generate/${id}/status?token=${token}`);
audio.src = `http://127.0.0.1:17493/audio/${id}?token=${token}`;
```

Media tokens last 30 minutes (`expires_in` is in seconds), carry the role of the key that requested them, and are accepted only on `GET` media and progress routes: generation audio, avatars, samples, exports, capture audio, and the status, download-progress and speak-event streams. A server restart invalidates every token, so fetch a new one when a `GET` with `?token=` starts failing with `401`. The Voicebox UI does exactly this for you.

## Public endpoints

A few paths work without a key:

- `GET /health` answers `{"status": "healthy", "service": "voicebox"}`. The full body (loaded model, GPU, backend variant) requires a key.
- `GET /` answers a short JSON banner (or, in Docker, the web UI).
- `GET /cloud/callback`, the browser redirect used by cloud pairing.
- `/docs`, `/redoc` and `/openapi.json`, the interactive API reference. Set `VOICEBOX_DISABLE_DOCS=1` to remove them, which is recommended for headless servers.
- In Docker, the web UI's static files and page navigations, so that the Connect screen can load.

Anonymous requests are rate-limited per IP address.

## Rate limits

Limits are token buckets per key, refilled continuously (a limit of 300 per minute refills at 5 per second). Defaults:

| Limit | Admin key | Client key | Notes |
|-------|-----------|------------|-------|
| Requests per minute | 1200 | 300 | Every authenticated request |
| Inference requests per minute | 120 | 30 | TTS, STT and LLM routes, plus the MCP `speak` and `transcribe` tools |
| Upload bytes per minute | 2 GiB | 256 MiB | Request bodies, from `Content-Length` or counted as they arrive |
| TTS characters per minute | 600,000 | 60,000 | The `text` of each `/generate`, `/generate/stream` and `/speak` call |
| Pending queued jobs | unlimited | 4 | Generations waiting in or running through the queue at once |
| Global queue depth | 32 | 32 | Whole server, all keys together; `VOICEBOX_MAX_QUEUE_DEPTH` |
| Failed authentications per minute | 30 per IP | 30 per IP | Bad keys and `403`s; a valid key keeps working regardless |
| Anonymous requests per minute | 300 per IP | 300 per IP | The public endpoints above |

Every limited response carries `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`; a rejected request gets `429` with `Retry-After`. A full queue also answers `429`.

Per-key overrides live in the `limits` object of each entry in `api_keys.json`, which is what the `--limit` flags of `backend.keys create` and the `limits` field of `POST /auth/keys` write. The fields are `requests`, `inference`, `uploads_bytes`, `tts_chars` and `max_pending_jobs`; `null` means unlimited.

```json
{
  "id": "batch-job",
  "role": "client",
  "limits": { "requests": 600, "inference": 60, "tts_chars": null }
}
```

`VOICEBOX_RATE_LIMITING=0` turns the buckets off for a trusted environment. The queue depth and the request-body caps stay in force.

### Request-body caps

Bodies above the cap are rejected with `413`:

| Route | Cap |
|-------|-----|
| JSON routes | 2 MiB |
| `/transcribe`, `/captures` | 200 MiB |
| `/profiles/import` | 100 MiB |
| `/profiles/{id}/samples`, `/history/import` | 50 MiB |
| `/profiles/{id}/avatar` | 10 MiB |
| `/mcp` (base64 audio for `voicebox.transcribe`) | 64 MiB |

## Errors

| Status | Body | Meaning |
|--------|------|---------|
| `401` | `{"detail": "Authentication required"}` | No key was sent. The response also carries `WWW-Authenticate: Bearer realm="voicebox"`. |
| `401` | `{"detail": "Invalid API key"}` | The key is unknown or revoked. An expired or invalid media token answers `401` too. |
| `403` | `{"detail": "Admin key required"}` | A client key called an admin route. |
| `413` | | The request body exceeds the cap for that route. |
| `429` | | A rate limit or the queue is exhausted. Wait `Retry-After` seconds. |
| `500` | `{"detail": "Internal server error", "error_id": "..."}` | Something unexpected happened. Details are never sent to clients; search the server log for the `error_id`. |

The server's access log redacts `token=` values, so it is safe to share when you report a problem.

## Rotating and revoking keys

- **Client keys**: create the replacement, move the app over, then `revoke` the old id. Revocation is immediate, including for media tokens minted from that key.
- **`VOICEBOX_API_KEY`**: change the variable and restart the server (`docker compose up -d` after re-exporting it).
- **`api_key` file**: stop the server, delete the file, and start again; a new key is generated. Quit the desktop app first if it is the app's server. MCP clients that were given the old key need the new one; the stdio shim picks it up automatically on the same machine.

## Environment variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `VOICEBOX_API_KEY` | unset | One admin key (id `env`). Empty counts as unset. |
| `VOICEBOX_API_KEY_FILE` | `<data-dir>/api_key` | Where the auto-generated admin key is stored. |
| `VOICEBOX_API_KEYS_JSON` | `<data-dir>/api_keys.json` | The hashed store for created keys. |
| `VOICEBOX_DISABLE_DOCS` | unset | `1` removes `/docs`, `/redoc` and `/openapi.json`. |
| `VOICEBOX_RATE_LIMITING` | `1` | `0` disables the per-key and per-IP buckets. |
| `VOICEBOX_MAX_QUEUE_DEPTH` | `32` | Maximum number of queued generation jobs across all keys. |
| `VOICEBOX_CORS_ORIGINS` | local origins | Comma-separated extra browser origins allowed to call the API. |
| `FORWARDED_ALLOW_IPS` | loopback | Proxies whose `X-Forwarded-For` the server trusts for per-IP limits. Set it to your reverse proxy's address; never `*` on a published port. |
