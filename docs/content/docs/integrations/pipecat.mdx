[Pipecat](https://docs.pipecat.ai/) handles the browser connection, voice activity detection, interruptions, and conversation. Voicebox supplies speech and transcription through its [OpenAI-compatible API](/overview/api-reference). The runnable example lives in `integrations/pipecat/` in the repository.

| Component | Implementation |
|---|---|
| Browser audio | Pipecat SmallWebRTC transport and development runner |
| Turn detection | Local Silero VAD |
| Transcription | Small adapters over Pipecat's `OpenAIRealtimeSTTService` and `OpenAISTTService` |
| Speech | `VoiceboxTTSService` (HTTP default) or `VoiceboxStreamingTTSService` (incremental WebSocket), both 24 kHz PCM |
| Replies | Any OpenAI-compatible chat server, or the example's local echo mode |

Pipecat 1.15's stock OpenAI TTS service validates voices against OpenAI's catalog. Both adapters allow Voicebox preset IDs such as `af_heart` and cloned voice names or IDs. The default HTTP adapter uses Pipecat's sentence aggregation, closes interrupted streams, and disables automatic SDK retries. The optional WebSocket adapter consumes tokens and flushes bounded phrases. Neither replays speech after a failure.

The transcription adapters identify completed Voicebox results and close the batch service's HTTP pool when a call ends. Realtime turns wait for every locally committed fragment before finalizing. The underlying HTTP and realtime protocols remain Pipecat's OpenAI implementations.

Realtime resampling uses float filtering with explicit PCM rounding. This keeps digital silence exact, preserving quiet speech and streaming filter tails without integer dither that can trigger Whisper hallucinations while the caller is idle.

## Start a browser conversation

Start a Voicebox server with `kokoro,whisper-base` in `VOICEBOX_PRELOAD_MODELS` and wait for `/health/ready` to return `200`. See the [deployment guide](/overview/deployment) for server setup. Use a client key with enough capacity for a conversation; from the Voicebox repository root:

```bash
backend/venv/bin/python -m backend.keys create --id pipecat-agent --role client \
  --limit inference=600 --limit requests=1200 \
  --limit max_pending_jobs=16 --limit max_realtime_sessions=8
```

Add `--data-dir` when the server uses a separate data directory. Keep the printed key for `VOICEBOX_CLIENT_KEY`. The server-wide `VOICEBOX_REALTIME_MAX_SESSIONS` limit defaults to four, independently of the key's limit.

Install the example in its own Python 3.11+ environment, separate from `backend/venv`:

```bash
python3 -m venv /tmp/voicebox-pipecat
/tmp/voicebox-pipecat/bin/pip install -r integrations/pipecat/requirements.txt
export VOICEBOX_URL=http://127.0.0.1:17493
export VOICEBOX_CLIENT_KEY=<client-key>
export VOICEBOX_LLM=echo
/tmp/voicebox-pipecat/bin/python integrations/pipecat/bot.py -t webrtc
```

Open the local URL printed by Pipecat's runner, connect, and allow microphone access. Echo mode repeats your words as “You said: …”, so speech can be checked without an LLM account. The browser connects to Pipecat; the Voicebox key stays in the Python process.

For a conversational LLM, set `VOICEBOX_LLM=openai` and `OPENAI_API_KEY`, or configure `LLM_BASE_URL`, `LLM_MODEL`, and `LLM_API_KEY` for your own chat server. Voicebox's `/v1` API has no chat-completions endpoint.

## Settings

| Variable | Default | Purpose |
|---|---|---|
| `VOICEBOX_URL` | `http://127.0.0.1:17493` | Server root or URL ending in `/v1` |
| `VOICEBOX_CLIENT_KEY` | Required | Voicebox client key; separate from LLM credentials |
| `VOICEBOX_VOICE` | `af_heart` | Preset voice ID or cloned voice name/ID |
| `VOICEBOX_TTS_MODEL` | `tts-1` | Uses the voice's engine; explicit model IDs are also accepted |
| `VOICEBOX_TTS_TRANSPORT` | `http` | HTTP sentence synthesis or `websocket` incremental phrase synthesis |
| `VOICEBOX_PRONUNCIATIONS_FILE` | Unset | JSON object of literal pronunciation replacements |
| `VOICEBOX_TTS_SPEED` | Server default | Speech rate from 0.25 to 4 |
| `VOICEBOX_TTS_INSTRUCTIONS` | Unset | Engine-supported delivery instructions, maximum 500 characters |
| `VOICEBOX_FIRST_CHUNK_CHARS` | Server default | Backend first chunk text budget, 20–1000 characters |
| `VOICEBOX_MAX_CHUNK_CHARS` | Server default | Backend later chunk text budget, 100–5000 characters |
| `VOICEBOX_TEXT_FLUSH_CHARS` | `120` | WebSocket only: phrase text budget, 20–1000 characters |
| `VOICEBOX_TTS_TIMEOUT` | `120` | WebSocket only: speech progress timeout in seconds, 1–1800 |
| `VOICEBOX_STT_MODEL` | `whisper-1` | Uses the server's current Whisper model |
| `VOICEBOX_LANGUAGE` | `en` | Transcription language |
| `VOICEBOX_STT_REALTIME` | `1` | `1` streams transcription; `0` uploads each utterance |
| `VOICEBOX_LLM` | `openai` | `echo` runs without an external LLM |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | OpenAI, `gpt-4.1-mini`, `OPENAI_API_KEY` | Chat provider; custom endpoints use an explicit key or a local placeholder |

Realtime mode streams audio to `/v1/realtime?intent=transcription`. Pipecat's local VAD commits utterances. Whisper and faster-whisper produce rolling partial passes; optional Nemotron uses cached native streaming state between chunks. Set `VOICEBOX_STT_MODEL` to a model ID from `/v1/models` after [installing and preloading its runtime](/developer/transcription). Batch mode posts VAD-cut recordings to `/v1/audio/transcriptions`.

## Realtime turn handling in your own pipeline

Pair the realtime adapter with `VoiceboxSpeechTimeoutUserTurnStopStrategy(stt)`. The example already wires this strategy. For a custom pipeline with `integrations/pipecat/` on the Python import path:

```python
import os
from pipecat.audio.vad.silero import SileroVADAnalyzer
from pipecat.processors.aggregators.llm_response_universal import LLMUserAggregatorParams
from pipecat.turns.user_turn_strategies import UserTurnStrategies
from services import VoiceboxSpeechTimeoutUserTurnStopStrategy, voicebox_stt

stt = voicebox_stt(
    api_key=os.environ["VOICEBOX_CLIENT_KEY"],
    base_url=os.environ["VOICEBOX_URL"],
    realtime=True,
)
user_params = LLMUserAggregatorParams(
    vad_analyzer=SileroVADAnalyzer(),
    user_turn_strategies=UserTurnStrategies(
        stop=[VoiceboxSpeechTimeoutUserTurnStopStrategy(stt)]
    ),
)
```

Pass `user_params` to `LLMContextAggregatorPair` and place `stt` before its user aggregator. Short pauses can create multiple local VAD commits while CPU transcription is still pending. The custom strategy preserves all transcript fragments and holds the turn open until the outstanding results arrive, preventing a late fragment from interrupting the reply. It adds no fixed wait after the last result. Unresolved commits fail explicitly after 120 seconds by default; direct `VoiceboxRealtimeSTTService` construction accepts `commit_timeout_s`. Batch mode uses the stock `SpeechTimeoutUserTurnStopStrategy`.

## Incremental speech

Set `VOICEBOX_TTS_TRANSPORT=websocket` to use `/v1/audio/speech/stream`. This adapter consumes Pipecat LLM **tokens**, flushing at sentence punctuation or a word boundary near `VOICEBOX_TEXT_FLUSH_CHARS`, and flushes the remainder when the LLM response ends. It can start speech before the full sentence arrives. Each phrase is held locally, then appended and flushed atomically; the server only synthesizes flushed text.

At most four phrases of 1000 characters are outstanding, keeping long LLM responses below Voicebox's 10000-character pending text limit. Audio queued ahead of SDK playback is bounded to 64 frames; a consumer stalled for five seconds fails. An interruption cancels the affected flushes and drops unsent text while preserving SDK speech explicitly marked uninterruptible. A model chunk already executing may finish. Connection loss or malformed or partial audio produces a pipeline error, without replaying submitted speech.

Both transports support speed, engine-supported instructions, pronunciation dictionaries, and backend chunk controls. A pronunciation file looks like `{"API":"A P I","Voicebox":"Voice box"}` and allows at most 100 entries, 128-character keys, 256-character values, and 8192 total characters. Replacement matches stay within each phrase. Pipecat `TTSUpdateSettingsFrame` can update `VoiceboxStreamingTTSService.Settings`; streaming settings take effect on the next LLM turn.

WebSocket TTS holds one additional socket per call. With realtime STT, each call uses **two** slots from the client's shared `max_realtime_sessions` quota. Speech sockets also count against `VOICEBOX_SPEECH_MAX_SESSIONS` (default four). Each flushed phrase consumes an inference request. HTTP remains the default because shorter phrases trade speech continuity and inference volume for earlier audio; measure this tradeoff with your selected voice and LLM.

## Validation and deployment

The integration pins Pipecat 1.15.0 and includes server-free contract tests, a speech roundtrip check, and a complete WebRTC conversation check against a running Voicebox:

```bash
python integrations/pipecat/smoke.py --stt both
python integrations/pipecat/e2e.py --stt realtime
python integrations/pipecat/e2e.py --stt batch
python integrations/pipecat/smoke.py --tts websocket --stt both
python integrations/pipecat/e2e.py --tts websocket --stt realtime
python integrations/pipecat/e2e.py --tts websocket --turns 3 --barge-in --idle-between 18
```

Run these in the example's environment with `VOICEBOX_URL` and `VOICEBOX_CLIENT_KEY` set. The WebRTC check starts its own local agent and scripted caller, records the greeting and reply, verifies their transcripts, and stops its runner. It needs no browser, microphone, or paid LLM.

`--turns` repeats exchanges on the same connection; `--barge-in` interrupts every cycle and checks the follow-up. `--duration 1800` continues the conversation for at least 30 minutes. Echo is the default; `--llm configured` uses your chat provider and checks intelligible speech and timing without requiring replies to repeat the caller. The separate manual/weekly speech reliability workflow runs isolated model-backed conversations and server restarts. See `docs/walkthroughs/10-speech-reliability.md` for local orchestration, idle reconnect checks and artifact details.

On 2026-11-03, both WebRTC modes passed against Kokoro and MLX Whisper Base on Apple Silicon with zero word errors. Replies began 1.057 s after the caller finished in realtime mode and 1.078 s in batch mode. These single-session checks use an echo LLM and do not measure production capacity. CI runs the server-free checks in a separate environment from the backend and LiveKit.

The browser runner is a local development example. Public deployment needs authentication on the agent's transport/signaling endpoint, HTTPS, and appropriate WebRTC connectivity. Keep Voicebox and Pipecat close together to limit latency, preload models, and size concurrent calls against Voicebox's synthesis queue and shared Whisper slot. GPU capacity, phone transports, and external LLM quality need validation in the intended deployment.
