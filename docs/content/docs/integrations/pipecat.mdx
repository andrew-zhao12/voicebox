[Pipecat](https://docs.pipecat.ai/) handles the browser connection, voice activity detection, interruptions, and conversation. Voicebox supplies speech and transcription through its [OpenAI-compatible API](/overview/api-reference). The runnable example lives in `integrations/pipecat/` in the repository.

| Component | Implementation |
|---|---|
| Browser audio | Pipecat SmallWebRTC transport and development runner |
| Turn detection | Local Silero VAD |
| Transcription | Small adapters over Pipecat's `OpenAIRealtimeSTTService` and `OpenAISTTService` |
| Speech | `VoiceboxTTSService`, a small Pipecat adapter for streaming 24 kHz PCM |
| Replies | Any OpenAI-compatible chat server, or the example's local echo mode |

Pipecat 1.15's stock OpenAI TTS service validates voices against OpenAI's catalog. The example's adapter allows Voicebox preset IDs such as `af_heart` and cloned voice names or IDs. It uses Pipecat's sentence aggregation and interruption handling, closes interrupted HTTP streams, and disables automatic SDK retries to avoid replaying speech.

The transcription adapters mark completed Voicebox utterances as final for Pipecat's turn handling and close the batch service's HTTP pool when a call ends. The underlying HTTP and realtime protocols remain Pipecat's OpenAI implementations.

## Start a browser conversation

Start a Voicebox server with `kokoro,whisper-base` in `VOICEBOX_PRELOAD_MODELS` and wait for `/health/ready` to return `200`. See the [deployment guide](/overview/deployment) for server setup. Use a client key with enough capacity for a conversation; from the Voicebox repository root:

```bash
backend/venv/bin/python -m backend.keys create --id pipecat-agent --role client \
  --limit inference=600 --limit requests=1200 \
  --limit max_pending_jobs=16 --limit max_realtime_sessions=8
```

Add `--data-dir` when the server uses a separate data directory. Keep the printed key for `VOICEBOX_CLIENT_KEY`. The server-wide `VOICEBOX_REALTIME_MAX_SESSIONS` limit defaults to four, independently of the key's limit.

Install the example in its own Python 3.11+ environment, separate from `backend/venv`:

```bash
python3 -m venv /tmp/voicebox-pipecat
/tmp/voicebox-pipecat/bin/pip install -r integrations/pipecat/requirements.txt
export VOICEBOX_URL=http://127.0.0.1:17493
export VOICEBOX_CLIENT_KEY=<client-key>
export VOICEBOX_LLM=echo
/tmp/voicebox-pipecat/bin/python integrations/pipecat/bot.py -t webrtc
```

Open the local URL printed by Pipecat's runner, connect, and allow microphone access. Echo mode repeats your words as “You said: …”, so speech can be checked without an LLM account. The browser connects to Pipecat; the Voicebox key stays in the Python process.

For a conversational LLM, set `VOICEBOX_LLM=openai` and `OPENAI_API_KEY`, or configure `LLM_BASE_URL`, `LLM_MODEL`, and `LLM_API_KEY` for your own chat server. Voicebox's `/v1` API has no chat-completions endpoint.

## Settings

| Variable | Default | Purpose |
|---|---|---|
| `VOICEBOX_URL` | `http://127.0.0.1:17493` | Server root or URL ending in `/v1` |
| `VOICEBOX_CLIENT_KEY` | Required | Voicebox client key; separate from LLM credentials |
| `VOICEBOX_VOICE` | `af_heart` | Preset voice ID or cloned voice name/ID |
| `VOICEBOX_TTS_MODEL` | `tts-1` | Uses the voice's engine; explicit model IDs are also accepted |
| `VOICEBOX_STT_MODEL` | `whisper-1` | Uses the server's current Whisper model |
| `VOICEBOX_LANGUAGE` | `en` | Transcription language |
| `VOICEBOX_STT_REALTIME` | `1` | `1` streams transcription; `0` uploads each utterance |
| `VOICEBOX_LLM` | `openai` | `echo` runs without an external LLM |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | OpenAI, `gpt-4.1-mini`, `OPENAI_API_KEY` | Chat provider; custom endpoints use an explicit key or a local placeholder |

Realtime mode streams audio to `/v1/realtime?intent=transcription`. Pipecat's local VAD commits utterances; Voicebox transcribes them with Whisper. This remains utterance-based recognition, rather than a token-streaming ASR model. Batch mode posts VAD-cut recordings to `/v1/audio/transcriptions`.

## Validation and deployment

The integration pins Pipecat 1.15.0 and includes server-free contract tests, a speech roundtrip check, and a complete WebRTC conversation check against a running Voicebox:

```bash
python integrations/pipecat/smoke.py --stt both
python integrations/pipecat/e2e.py --stt realtime
python integrations/pipecat/e2e.py --stt batch
```

Run these in the example's environment with `VOICEBOX_URL` and `VOICEBOX_CLIENT_KEY` set. The WebRTC check starts its own local agent and scripted caller, records the greeting and reply, verifies their transcripts, and stops its runner. It needs no browser, microphone, or paid LLM.

On 2026-11-03, both WebRTC modes passed against Kokoro and MLX Whisper Base on Apple Silicon with zero word errors. Replies began 1.057 s after the caller finished in realtime mode and 1.078 s in batch mode. These single-session checks use an echo LLM and do not measure production capacity. CI runs the server-free checks in a separate environment from the backend and LiveKit.

The browser runner is a local development example. Public deployment needs authentication on the agent's transport/signaling endpoint, HTTPS, and appropriate WebRTC connectivity. Keep Voicebox and Pipecat close together to limit latency, preload models, and size concurrent calls against Voicebox's synthesis queue and shared Whisper slot. GPU capacity, phone transports, and external LLM quality need validation in the intended deployment.
