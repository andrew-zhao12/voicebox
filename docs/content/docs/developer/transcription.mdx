Voicebox uses Whisper by default: MLX on Apple Silicon and Transformers/PyTorch elsewhere. Optional faster-whisper and Nemotron runtimes share the same upload and realtime APIs. Voice-sample auto-fill continues to use the default Whisper backend.

## Models and capabilities

`GET /v1/models` returns model IDs, languages, download/load state, runtime availability and capability flags. Downloaded weights and an installed runtime are separate requirements.

| IDs | Runtime | Native streaming | Vocabulary hints | Word timestamps |
|---|---|---|---|---|
| `whisper-base`, `whisper-small`, `whisper-medium`, `whisper-large`, `whisper-turbo` | Built-in MLX or PyTorch | No; rolling partial passes | `prompt`, `hotwords` | Yes |
| `faster-whisper-base`, `faster-whisper-small`, `faster-whisper-medium`, `faster-whisper-large`, `faster-whisper-turbo` | Optional CTranslate2 | No; rolling partial passes | `prompt`, `hotwords` | Yes |
| `nemotron-streaming-en-0.6b` | Isolated Transformers worker | Yes; cached encoder and RNNT decoder | Unsupported | Unsupported |
| `nemotron-streaming-multilingual-0.6b` | Isolated Transformers worker | Yes; cached encoder and RNNT decoder | Unsupported | Unsupported |

Large maps to Whisper Large v3; Turbo maps to Large v3 Turbo. Base, Small and Medium advertise Whisper's 99 languages; Large and Turbo also include Cantonese (`yue`). Nemotron English supports English; the multilingual model advertises its 32 usable locales, excluding adaptation-only locales. Consult each model's returned `languages` list.

`whisper-1`, `gpt-4o-transcribe` and `gpt-4o-mini-transcribe` remain aliases for the current default Whisper size. They do not invoke OpenAI's hosted models. Bare sizes (`base`, `small`, `medium`, `large`, `turbo`) remain valid for existing clients.

## Optional runtimes

Install faster-whisper into the Python environment that runs the server:

```bash
backend/venv/bin/python -m pip install -r backend/requirements-faster-whisper.txt
```

Set `VOICEBOX_FASTER_WHISPER_DEVICE=cpu` or `cuda` (default `auto`). `VOICEBOX_FASTER_WHISPER_COMPUTE_TYPE` overrides the runtime's compute type; CPU defaults to `int8`, CUDA to `float16`. `VOICEBOX_REPLICA_THREADS` sets CPU threads. The requirements pin a compatible PyAV version. CUDA also needs the libraries required by the installed CTranslate2 build; verify them on the target host.

Nemotron requires Transformers 5, which conflicts with the desktop TTS stack. Install it into a **separate Python 3.12 environment** and point Voicebox at that interpreter:

```bash
python3.12 -m venv .venv-nemotron
.venv-nemotron/bin/python -m pip install -r backend/requirements-nemotron.txt
export VOICEBOX_NEMOTRON_PYTHON="$PWD/.venv-nemotron/bin/python"
export VOICEBOX_NEMOTRON_DEVICE=cpu  # auto or cuda are also supported
export VOICEBOX_PRELOAD_MODELS=kokoro,nemotron-streaming-en-0.6b
backend/venv/bin/python -m backend.main
```

`VOICEBOX_NEMOTRON_DELAY_MS` selects the model's streaming lookahead (default `560`; supported values are model-specific). Optional dependencies are not installed by the standard desktop/server environment. For containers, install the extra runtime in your derived image and set the same variables. `runtime_available` checks whether the package/interpreter is present; loading performs the full runtime validation.

Administrators download/load models through Model Management or `/models/download` and `/models/load`. Client keys can only use weights already cached. Preload the chosen IDs with `VOICEBOX_PRELOAD_MODELS` and wait for `/health/ready` before accepting calls.

## File transcription

Both `/transcribe` and `/v1/audio/transcriptions` accept multipart `file`, `model`, `language`, `prompt` and repeated `hotwords` fields. The OpenAI-compatible endpoint also supports `json`, `text`, `verbose_json`, `srt` and `vtt` output.

```bash
curl "$VOICEBOX_URL/v1/audio/transcriptions" \
  -H "Authorization: Bearer $VOICEBOX_CLIENT_KEY" \
  -F file=@recording.wav -F model=faster-whisper-base -F language=en \
  -F 'prompt=A discussion about speech software.' \
  -F hotwords=Voicebox -F hotwords=Pipecat \
  -F response_format=verbose_json -F 'timestamp_granularities[]=word'
```

`prompt` is bounded at 4,096 characters. `hotwords` accepts up to 100 non-empty terms, each at most 100 characters and at most 4,096 characters total. Whisper merges vocabulary into its initial prompt; faster-whisper passes vocabulary to its decoder's hotword option. Hints bias recognition; they do not guarantee a spelling. Unsupported options, including hints or word timing on Nemotron, return a clear error.

Word timings require `response_format=verbose_json`. The returned `words` array contains actual aligned `word`, `start` and `end` values in seconds; no timings are synthesized by distributing text across the clip. Segment timings remain available for subtitle output. Nemotron segments describe decoder emission spans, not forced word alignment.

Audio is decoded and normalized into an inference-owned WAV. Cancelling an upload does not delete that file while a model thread still needs it. Whisper handles recordings longer than its 30-second window through its runtime's long-form path.

## Realtime recognition

`WS /v1/realtime?intent=transcription` serves the OpenAI GA transcription protocol. `/v1/realtime/transcription` serves Voicebox's beta-shaped session events. See the [wire protocol](/overview/api-reference#live-transcription-ws-v1realtime).

Whisper and faster-whisper re-transcribe the accumulated utterance for partial results. Nemotron consumes **only new audio** and retains per-utterance encoder/decoder caches; independent sockets do not share decoder state. Both paths use the same VAD/manual commits, stable partial deltas and authoritative final transcript. The existing 30-second utterance bound applies to all models.

Configure hints and timing inside the transcription object:

```json
{
  "type": "session.update",
  "session": {
    "type": "transcription",
    "audio": {"input": {
      "format": {"type": "audio/pcm", "rate": 16000},
      "transcription": {
        "model": "whisper-base", "language": "en",
        "prompt": "Software discussion.", "hotwords": ["Voicebox"],
        "word_timestamps": true
      },
      "turn_detection": null
    }}
  }
}
```

With `word_timestamps: true`, completed events include `words`. Commit or clear the current audio before changing model, language, hints or timing settings. Already queued utterances retain their original settings. Native models reject unsupported hints/timing.

## Concurrency and lifecycle

All STT work uses the shared `whisper_slot`, including optional engines. At most four callers wait, with a 60-second wait limit; excess work gets `429` or the socket's `whisper_busy` error. A cancelled caller retains its inference slot until its underlying work finishes.

Native streaming holds the slot per operation, not for a socket's entire lifetime. Each decoder stream pins its model against unload or model switching. Clear, disconnect and finalization release decoder state after any in-flight operation finishes. Model Management, preloading and idle unload use the same guards.

Use the repository's [speech benchmark walkthrough](https://github.com/jamiepine/voicebox/blob/main/docs/walkthroughs/08-speech-benchmarks.md) to measure accuracy, latency, concurrency and memory on your recordings and deployment hardware. CPU smoke tests establish execution correctness; they do not establish GPU capacity.
